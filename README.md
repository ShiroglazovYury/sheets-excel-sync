# sheets-excel-sync — данные из Google Sheets в Excel по кнопке

Проект по курсу Python (ИИМУП, НИУ ВШЭ, 2026), тема «Автоматизируй свою рутину».

## Какая была рутина

На работе финансовые модели с прогнозом операционных метрик живут в Google
Sheets, а вся управленческая отчётность — в Excel. Чтобы обновить прогноз
в Excel-модели, приходилось:

1. скачать Google-таблицу файлом `.xlsx` (на больших таблицах Google
   отказывает: «This file is too large to be exported»);
2. открыть его, найти нужный диапазон в десятки тысяч строк;
3. скопировать его и вставить значениями в модель. Excel на этом надолго
   подвисает, потому что пересчитывает формулы.

Выходило около 20–30 минут на одно обновление, несколько раз в месяц, и
каждый раз оставался риск вставить не тот диапазон или «съехать» на строку.

**Сейчас** это одна кнопка в Excel. Программа сама забирает диапазон через
Google Sheets API, чистит и проверяет данные, записывает их в нужный лист
(40 000 строк — примерно 10 секунд) и пишет, что изменилось с прошлого раза.
Если данные в источнике сломаны, Excel она не трогает.

Рабочую систему с корпоративными данными в репозиторий выкладывать нельзя.
Поэтому здесь та же программа на **полностью синтетических данных** —
продажах шести вымышленных металлургических компаний
([`scripts/generate_demo_data.py`](scripts/generate_demo_data.py)). Порядки
цен и объёмов сверены с открытыми источниками, но все названия и числа
выдуманы. Структура такая же, как в рабочей задаче:

| Лист Google Sheets | Что это | Размер |
|---|---|---|
| `Forecast Inputs` | «широкий» прогноз: строка на метрику (объём / цена / выручка) × компанию × продукт × рынок × канал, столбец на месяц 2023-01…2027-12 | 1 440 строк × 67 столбцов |
| `Orders` | журнал заказов | 40 000 строк × 9 столбцов |

## Как это работает

```
 Кнопка в Excel ──► VBA (PERSONAL.XLSB) ──► xlwings RunPython ──► sheetsync.excel_entry
                                                                        │
             ┌──────────────────────────────────────────────────────────┘
             ▼
  source.py        читаем диапазон из Google Sheets (сервисный аккаунт, gspread)
  cleaning.py      чиним числа/даты/пробелы, мусор → пусто + предупреждение
  validation.py    проверяем структуру и бизнес-правила; ошибка → стоп, Excel не трогаем
  diff.py          сравниваем с прошлым успешным синком (по ключу строки)
  excel_target.py  пишем в открытую книгу через сам Excel (xlwings/COM)
  backup.py        снимок того, что записали, → backups/*.xlsx
  state.py         история запусков и последний снимок → state/sync_state.sqlite
```

Всё это связывает `runner.py` (`SyncRunner`). Тот же сценарий доступен из
консоли через `python -m sheetsync`, это удобно для отладки и диагностики.

### Модули

| Файл | Что внутри |
|---|---|
| [`config.py`](sheetsync/config.py) | Загрузка `config.yaml` в dataclass-ы. Конфиг целиком проверяется сразу при старте, а не падает через минуту на середине синка. |
| [`errors.py`](sheetsync/errors.py) | Иерархия ошибок. У всех «ожидаемых» ошибок (`SyncError`) текст написан для человека. Всё остальное считается багом и уходит в crash-лог. |
| [`table.py`](sheetsync/table.py) | `Table` — заголовок + строки + номера строк в исходном листе, чтобы сообщения ссылались на ту строку, которую человек видит в Google Sheets. |
| [`auth.py`](sheetsync/auth.py) | Ключ сервисного аккаунта или OAuth-токен; тип определяется по содержимому файла. |
| [`source.py`](sheetsync/source.py) | `GoogleSheetSource`: чтение диапазона, перевод ошибок API на человеческий язык, повтор запросов при лимитах Google. |
| [`cleaning.py`](sheetsync/cleaning.py) | Разбор чисел, дат и текста по правилам (см. «Краевые случаи»). |
| [`validation.py`](sheetsync/validation.py) | Проверки двух уровней: `error` блокирует запись, `warning` только сообщает. |
| [`diff.py`](sheetsync/diff.py) | Что добавилось, что пропало, какие ячейки и насколько изменились. |
| [`state.py`](sheetsync/state.py) | `StateStore`: SQLite с журналом запусков и снимком последних данных. |
| [`excel_target.py`](sheetsync/excel_target.py) | `ExcelTarget`: очистка старых данных, форматы, запись кусками, лист журнала. |
| [`backup.py`](sheetsync/backup.py) | Бэкап `.xlsx` и удаление старых файлов (хранится `backup_keep` штук). |
| [`runner.py`](sheetsync/runner.py) | `SyncRunner` — сценарий синка от чтения до журнала. |
| [`cli.py`](sheetsync/cli.py) | Команды `run`, `history`, `check`. |
| [`excel_entry.py`](sheetsync/excel_entry.py) | Функции для кнопок: любой исход превращается в понятное окно в Excel. |

**Где классы, а где функции.** Классы там, где есть состояние, которое
живёт между вызовами:
- `GoogleSheetSource` держит открытое соединение с таблицей;
- `ExcelTarget` держит найденную книгу;
- `StateStore` держит соединение с БД и работает как контекстный менеджер;
- `SyncRunner` получает источник, Excel и состояние через конструктор,
  поэтому в тестах их легко подменить на поддельные (`tests/test_runner.py`).

Преобразования без состояния — очистка, проверки, diff — написаны обычными
функциями. Результаты описаны через `dataclass`.

### Собственная логика

- **Блокирующие проверки** — данные в модель не пишутся:
  - нет обязательного столбца (с подсказкой, если он есть с другим регистром);
  - дубли или пустые ключи строк;
  - строк меньше `min_rows`;
  - строк стало резко меньше, чем в прошлый раз (`max_row_drop_pct`; осознанно
    пропустить такую проверку можно через `--force`);
  - доля нечитаемых чисел выше `max_bad_values_pct`: значит, столбцы съехали.
- **Предупреждения** — данные пишутся, но человек о них узнаёт:
  - отдельные мусорные ячейки;
  - отрицательные значения;
  - **выручка не сходится с объём × цена** с допуском 1%. Это бизнес-правило
    прогноза, оно ловит «ручные правки» выручки в источнике.
- **Не перезаписывать то, что не изменилось.** Если отпечаток данных (SHA-256)
  совпадает с прошлым успешным синком, Excel не трогаем.
- **Diff по ключу, а не по номеру строки.** Если в середину источника вставили
  строку, изменилась только она, а не всё, что ниже.

### Состояние между запусками

| Где | Что |
|---|---|
| `state/sync_state.sqlite`, таблица `runs` | журнал всех запусков: время, задание, статус (`success` / `unchanged` / `dry-run` / `failed`), строк, что изменилось |
| `state/sync_state.sqlite`, таблица `snapshots` | последний записанный срез по каждому заданию (gzip-JSON); с ним сравнивается следующий запуск |
| `backups/*.xlsx` | снимок каждого успешного синка, хранятся последние 10 |
| `reports/*.txt` | полный список проблем в данных (в окне Excel видны только первые 5) |
| лист `Sync Log` в книге | журнал синков прямо в Excel |

SQLite, а не JSON-файл, потому что запись атомарная: если Excel закрыть
посреди синка, полузаписанного файла не останется. Историю к тому же удобно
фильтровать запросами.

## Краевые случаи

Все случаи ниже встретились на практике или подмешаны в демо-данные
(список подмешанного печатает `generate_demo_data.py`).

**Грязные данные в источнике**

| Случай | Что делаем |
|---|---|
| Число текстом из русского Excel: `1 234,56`, неразрывные пробелы, `1.234,5`, `(150)`, `12%` | Превращаем в число, считаем в сводке «исправлено автоматически». Одна запятая — это дробная часть: `1,234` = 1.234 (русская локаль). |
| `n/a`, `-`, `—`, `#N/A`, `нет данных` | Пустая ячейка (не ноль: «нет данных» и 0 — разные вещи). |
| `#REF!`, `уточнить` в числовом столбце | Пустая ячейка + предупреждение с номером строки и столбцом. |
| Мусора больше порога (2% / 5%) | Стоп: похоже, столбцы съехали. Писать такое в модель нельзя. |
| Даты `2026-03-15`, `15.03.2026`, `15/03/2026`, серийный номер | Все превращаем в дату. |
| Невозможные даты: `31.02.2026`, `2026-13-05`, `вчера` | Пусто + предупреждение. |
| `СтальГрад ` с пробелом в конце, двойные пробелы, регион из одних пробелов | Обрезаем, иначе СУММЕСЛИ в Excel посчитает «две разные компании». |
| Пустая строка-разделитель в середине, «рваные» строки API (хвостовые пустые ячейки Google обрезает) | Пустые строки выкидываем, короткие дополняем до ширины заголовка. Номера строк в сообщениях остаются как в Google Sheets. |
| Дубль ключа (`ORD-000001` дважды), пустой ключ | Стоп, в сообщении — номера строк. |
| Столбец переименован или удалён, `company` → `Company` | Стоп + подсказка «есть похожий столбец». |
| Строк стало намного меньше (кто-то удалил пол-листа) | Стоп; если так и задумано — `--force`. |
| Выручка «поправлена руками» и не сходится с объём × цена | Предупреждение: какая комбинация, какой месяц, на сколько процентов. |
| Отрицательные значения | Предупреждение. В заказах объём может быть отрицательным (возвраты), поэтому там проверяется только цена. |
| Появился или пропал месяц-столбец | Показываем в diff. |

**Excel**

| Случай | Что делаем |
|---|---|
| Заголовок `2026-03` Excel превращает в дату 01.03.2026, ИНН `0274051582` — в число без нуля | Ставим заголовкам и текстовым столбцам формат «Текст» до записи. |
| Через COM Excel читает коды формата в **локали Windows**: в русской локали `dd.mm.yyyy` сохраняется буквальным текстом, а `General` вызывает ошибку | Коды формата дат не задаём, форматы сбрасываем через `clear()`. Дату в ячейке с «Общим» форматом Excel сам показывает в формате локали. |
| Новых строк меньше, чем старых: снизу остался бы хвост старых данных | Перед записью очищаем всю старую область. |
| Excel пересчитывает формулы после каждого куска записи и «висит» | На время записи ставим ручной пересчёт, потом возвращаем исходный режим. |
| 40 000 строк за один COM-вызов иногда падают по памяти | Пишем кусками по 5 000 строк. |
| Книга лежит в папке OneDrive: Excel считает её путём `https://…`, и xlwings пытается открыть её второй раз | Ищем открытую книгу по имени файла. |
| Книга не открыта | Открываем сами. |
| Данные в Google не изменились | Не пишем в Excel вообще (статус `unchanged`). |
| Путь к папке с апострофом (`OCT'FRC`) ломал строку Python внутри VBA | Путь не вшит в VBA, он берётся из поля PYTHONPATH надстройки xlwings. |

**Окружение и доступы**

| Случай | Что делаем |
|---|---|
| Нет ключа, ключ битый, файл не того формата | Сообщение, где взять ключ и куда его положить. |
| Таблица не расшарена на сервисный аккаунт | Сообщение с email-ом, который нужно добавить в доступ. |
| Неверный ID таблицы, нет листа | Сообщение со списком листов, которые есть. |
| Диапазон за границами листа | Сообщение с реальным размером листа. |
| Нет интернета | «Нет связи с Google». |
| Лимиты Google (429/5xx) | Повтор с растущей паузой, но не дольше 16 секунд: из Excel дольше ждать нельзя. |
| Ошибка в `config.yaml` | Сообщение с точным путём ключа, например `jobs.orders.validation.min_rows`. |
| Повреждён файл состояния | Сообщение «удалите файл», данные не страдают. |
| Неожиданный баг | Вместо traceback — окно с кратким текстом и crash-лог в `reports/`. |

## Установка на новом компьютере

Нужны Windows, Microsoft Excel и Python 3.11+ (при установке с python.org
поставить галочку «Add python.exe to PATH»).

### 1. Проект и зависимости

```powershell
cd <папка проекта>
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pytest                      # 79 тестов, без сети и без Excel
```

### 2. Google Cloud: сервисный аккаунт

Почему сервисный аккаунт, а не личный OAuth-токен: ключ не надо обновлять
через браузер, и он не протухает через 7 дней, как refresh-токен
OAuth-приложения в режиме «Testing».

1. https://console.cloud.google.com → **Create project** (например, `sheets-excel-sync`).
2. **APIs & Services → Library** → найти **Google Sheets API** → **Enable**.
3. **IAM & Admin → Service Accounts → Create service account**. Имя любое,
   роли не нужны → **Done**.
4. Открыть созданный аккаунт → **Keys → Add key → Create new key → JSON**.
   Скачанный файл переименовать в `service_account.json` и положить в папку
   `secrets/` проекта. Эта папка в `.gitignore`, ключ в git не попадёт.
5. Скопировать email аккаунта (вида `…@….iam.gserviceaccount.com`).

### 3. Google-таблица с демо-данными

1. Создать пустую Google-таблицу в своём Google Drive.
2. **Настройки доступа** → добавить email сервисного аккаунта с ролью
   **Редактор** (редактор нужен только для загрузки демо-данных; потом
   можно понизить до «Читателя»).
3. Конфиг:
   ```powershell
   copy config.example.yaml config.yaml
   ```
   и вставить в `google.spreadsheet_id` ссылку на таблицу (можно целиком).
4. Загрузить данные и создать книгу Excel:
   ```powershell
   python scripts/seed_google_sheet.py
   python scripts/create_demo_workbook.py
   python -m sheetsync check
   ```
   `check` пройдёт по шагам (конфиг → ключ → таблица → листы → книга) и
   покажет `[!!]` там, где что-то не так.

### 4. Надстройка xlwings в Excel

1. Открыть Excel (пустую книгу) и, **не закрывая его**, выполнить:
   ```powershell
   .venv\Scripts\xlwings addin install
   ```
   Без открытого Excel команда может зависнуть.
2. Перезапустить Excel — появится вкладка **xlwings**.
3. На вкладке xlwings заполнить:
   - **Interpreter**: `<папка проекта>\.venv\Scripts\python.exe`
   - **PYTHONPATH**: `<папка проекта>`

   Эти поля иногда сбрасываются после переоткрытия Excel. Если кнопка
   перестала работать с `could not find interpreter` или
   `ModuleNotFoundError: sheetsync`, первым делом проверьте их.

### 5. Макросы в личной книге (PERSONAL.XLSB)

Кнопки вызывают макросы из личной книги макросов. Поэтому сама книга с
отчётом остаётся обычным `.xlsx`, без макросов внутри.

1. **Файл → Параметры → Настроить ленту** → включить вкладку **Разработчик**.
2. **Разработчик → Запись макроса** → «Сохранить в: Личная книга макросов» →
   OK → сразу **Остановить запись**. Так создаётся `PERSONAL.XLSB`.
3. `Alt+F11` → правой кнопкой на **VBAProject (PERSONAL.XLSB)** → **Import File…**:
   - `xlwings.bas` (путь покажет команда
     `python -c "import xlwings, os; print(os.path.join(os.path.dirname(xlwings.__file__), 'xlwings.bas'))"`);
   - `vba/SheetSync.bas` из проекта.
4. `Ctrl+S` в редакторе VBA, закрыть его.

### 6. Кнопки

`create_demo_workbook.py` сам рисует кнопки на листах Summary, Forecast и
Orders и привязывает их к `PERSONAL.XLSB!SyncAll / SyncForecast / SyncOrders`.
Если кнопок нет (например, книгу создали с `--no-buttons`):
**Вставка → Фигуры** → нарисовать → правой кнопкой → **Назначить макрос** →
«Макросы в: Все открытые книги» → `PERSONAL.XLSB!SyncAll`.

## Как пользоваться

**Из Excel:** открыть `excel/Steel_Management_Report.xlsx` → нажать
«Обновить всё» (или кнопку отдельного задания). По завершении появится окно:
сколько строк записано, что изменилось, какие проблемы в данных. Сохранить
книгу (`Ctrl+S`) — когда проверите результат, программа сама не сохраняет.

**Из консоли:**

```powershell
python -m sheetsync run all               # синк всех заданий
python -m sheetsync run forecast --dry-run  # прочитать и проверить, Excel не трогать
python -m sheetsync run orders --force    # записать, даже если не изменилось / строк стало резко меньше
python -m sheetsync history               # журнал запусков
python -m sheetsync check                 # диагностика установки
```

Коды выхода: `0` — успех, `1` — ошибка доступа или окружения, `2` — данные
не прошли проверку.

**Свои задания.** Новый диапазон добавляется в `config.yaml` в раздел
`jobs`: лист и диапазон источника, лист и ячейка в Excel, типы столбцов и
правила проверки. Код менять не нужно.

## Сценарий демонстрации

1. Показать источник в Google Sheets (1 440 × 60 и 40 000 строк) и пустые
   листы в Excel.
2. «Обновить всё» → около 20 секунд → окно с итогом и найденной грязью;
   формулы на листе Summary пересчитались.
3. Ещё раз «Обновить всё» → «ничего не изменилось — Excel не трогали».
4. `python scripts/simulate_update.py` (+5% к прогнозу цен одной компании и
   200 новых заказов) или поправить пару ячеек в Google руками →
   «Обновить всё» → diff: какие ячейки и на сколько процентов.
5. Сломать источник: продублировать `order_id` или переименовать столбец →
   «Обновить заказы» → отказ с номерами строк, Excel не изменился.
6. `python -m sheetsync history` — история запусков.

## Структура репозитория

```
sheetsync/            пакет с программой (см. «Модули»)
scripts/
  generate_demo_data.py   синтетические данные (детерминированно, SEED=42)
  seed_google_sheet.py    загрузка демо-данных в свою Google-таблицу
  create_demo_workbook.py демо-книга Excel с формулами и кнопками
  simulate_update.py      «обновление источника» для демонстрации diff
vba/SheetSync.bas     макросы для кнопок
tests/                pytest: очистка, проверки, diff, состояние, конфиг, сценарий синка
config.example.yaml   шаблон конфига (сам config.yaml — в .gitignore)
```

Не в git (см. `.gitignore`): `secrets/` (ключ Google), `config.yaml`,
`state/`, `backups/`, `reports/`, `excel/`, `demo_data/`.
